Tamanu v2.65 moves server errors that staff cannot act on out of red toasts and into a new 'System errors' view, where they can be reviewed and sent to support. # 🌟 Major Features and Changes

## Tamanu Desktop

### _System errors view_

Unexpected server errors no longer interrupt staff with a red toast that gives them nothing to act on. These errors are now recorded quietly and collected in a new 'System errors' view under 'Facility admin', where anyone can review them and send them to the support team. Errors that call for a specific action, such as the server being unreachable or a record having been edited by someone else, still show as a toast.

**Key features**

- **Available to every user** - 'System errors' is listed under 'Facility admin' in the sidebar for all users, with no permission required.
- **Unread indicator** - A red dot appears next to 'System errors' whenever there is a new error, and stays visible when the sidebar section is collapsed or the sidebar is retracted. Opening the view marks the current errors as read.
- **Sortable error list** - Each error shows its date and time and a message describing the failed request, most recent first. The list covers the current login session only: it clears on logout, and errors older than 24 hours are removed.
- **Send error log** - The 'Send error log' action sends the listed errors to support, with space for additional information and an optional email address for follow-up. Only the user's ID is included, with no other identifying details. Sent errors are removed from the list.
- **Configurable recipients** - Reports go to the Tamanu support team by default. Each facility can send them to its own recipients instead.
- **Admin panel unchanged** - Errors raised in the admin panel still show as toasts.

# 🔧 System Enhancements

- **Request status in send to pharmacy** - The 'Last sent' column on the encounter medications table and the 'Send to pharmacy' modal shows whether a medication's request is an 'Active request' or 'Dispensed', with the date and time it was sent on hover. Where a medication has several requests awaiting dispensing, the earliest is shown until it is dispensed or cancelled. Medications never sent to pharmacy show 'n/a'.
- **Insurance plans by facility** - Insurance plans can be restricted to a set of facilities through the reference data import, in the same way as drugs. Only plans available at the invoice's facility are offered when adding an insurance plan to an invoice. A plan with no facilities set remains available everywhere.
- **Portable X-ray** - A new 'X-ray (Portable)' imaging type is available, with its own list of areas to be imaged supplied as default reference data. Add it to the enabled imaging types in the admin panel settings to offer it to staff.

# 🐛 Tweaks and Bug Fixes

## Desktop

- **Forms and dialogs** - The date picker no longer overflows for months that span six weeks, confirmation modals use the correct colour for their primary button, and 'OK' is spelled consistently throughout.

## Mobile

- **Dialogs and sign-in** - Confirmations, warnings and notifications use the device's own dialogs and toasts, giving a consistent look across the app. 'Sign out' is now 'Log out', and the sign-in screen explains when a user has been logged out for inactivity. The 'Update' link in the 'Update required' alert works, and the sign-in screen shows the current Tamanu logo and colours.
- **Forms** - Autocomplete fields no longer lag or overlap neighbouring content, survey forms check answers when leaving a field rather than on every keystroke, and the photo question no longer gets stuck loading.
- **Sync and performance** - Sync sends less data by compressing what the device uploads, and skips unnecessary work when there is nothing new to receive. Further rendering and database work keeps screens responsive on lower-end devices.

## System

- **Sync** - A clash between patient display IDs no longer stops sync, and a record renamed while another takes its old name in the same sync no longer fails. Facility server setup is more robust against misconfiguration.
- **FHIR** - Changes to reference data no longer trigger a rebuild of every FHIR resource that uses it, which keeps reference data imports from flooding the FHIR job queue on integrated deployments.
- **Data integrity** - Record updates from Tamanu Desktop accept only the fields each screen is meant to change.

# ⚠️ Critical Upgrade Notes

### Required

**_System errors view_**

- Staff will stop seeing red toasts for unexpected server errors on Tamanu Desktop. Let teams, and anyone who supports them, know that these now appear in 'System errors' under 'Facility admin', marked by a red dot.
- Error reports go to the Tamanu support team by default. Decide whether any facility should send them elsewhere, and set its recipients if so.

**_Database changes_**

- The upgrade rebuilds a number of uniqueness rules on synced tables, including patients. Allow additional time in the upgrade window on large deployments.

### Optional

**_FHIR integrations_**

- Existing FHIR resources no longer update when the reference data they use changes, such as a renamed lab test type. They pick up the change the next time the resource itself is rebuilt. If an integration depends on reference data names being current, discuss this with the support team before upgrading.

**_Insurance plans by facility_**

- No action is needed: existing plans stay available at every facility. Add facilities to a plan in the reference data import only where you want to restrict it.

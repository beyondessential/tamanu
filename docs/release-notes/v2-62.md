Released 17-08-2026

Tamanu v2.62 is a modest release. Its main change is administrative: a large amount of server configuration moves into the admin panel. Clinically, the 'Send to pharmacy' workflow extends to discharge and prescribing, and lab requests gain out-of-range result flags.

---

# 🌟 Major Features and Changes

## System Administration

### _Configuration Managed in the Admin Panel_

Configuration that previously lived in files on each server is now database-backed settings, editable in the admin panel with validation and per-facility overrides. Existing values migrate automatically during the upgrade, so nothing needs re-entering and behaviour does not change.

**Key features**

- **Editable without server access** - Mail, scheduled tasks, integrations, localisation, reporting and rate limiting are managed in the admin panel.
- **Carried across on upgrade** - Existing configuration migrates automatically, and a value already set in settings is never overwritten.
- **Applied without a restart** - A saved setting takes effect on the next read, and the few that need a restart are marked.
- **High-risk settings protected** - Changing one now requires full administrative permission, enforced by the server.
- **Integration credentials encrypted** - Secrets use one deployment-wide key, generated by central and distributed to facilities over sync, so no key needs placing on a server by hand.

## Tamanu Desktop

### _'Send to Pharmacy' from Discharge and Prescribing_

Medications can now be sent to pharmacy at the two points where prescribing happens: writing a new prescription, and discharging a patient. At discharge the patient's encounter medications are ticked to send by default, with stock and previous requests visible while deciding.

**Key features**

- **At discharge** - A 'Send to pharmacy' column on the 'Discharge' modal, ticked for encounter medications and unticked for other ongoing medications.
- **When prescribing** - A 'Send to pharmacy' option on the 'New prescription' modal, off by default.
- **Dispensing quantity required** - 'Discharge qty' becomes 'Dispensing qty' and must be filled in.
- **Stock and history in view** - 'Stock' and 'Last sent' columns show availability, when a request was last sent, and whether it is still active or already dispensed.

The pharmacy fields appear only where the pharmacy order setting is enabled.

# 🔧 System Enhancements

- **Lab request result flags** - An individual 'Lab request' now highlights numeric results outside their reference range, matching the patient-level results table, with a tooltip naming the bound breached. Fields edited after entry carry an asterisk and a legend below the table.
- **Lab request priority** - Two settings control whether a priority must be chosen when a request is created, and whether it can be changed afterwards. Both default to current behaviour.
- **Vitals and charting time ranges** - 'Last 7 days', 'Last 30 days' and 'Last year' are available at the encounter level and for program registry charts.
- **Sync lookup self-healing** - The central sync lookup table now repairs rows whose source changed without advancing the sync clock, which is what happens during a migration. Healed rows keep their sync tick, so facilities do not re-download records they already hold.
- **Hard deletes in the audit changelog** - A permanently removed row is now recorded as it stood before removal and marked as a hard delete. Changelog writing and its attachment to sync are also more memory-efficient.

# 🐛 Tweaks and Bug Fixes

## Desktop

- **Invoicing** - 'Details' and 'Ordered by' are now required on every line, so clearing 'Details' no longer silently deletes it. The reason for a discount or mark-up is visible on the item row, and a stale sliding fee discount no longer survives a change of family size.
- **Medications** - The 'View patient' link opens the 'Patient summary' tab, the dispensed medication popup shows the medication actually dispensed, and 'Discontinued by' defaults to the current user.
- **Charts** - Edit-history timestamps display in local time.
- **Scheduling** - A booking running past midnight shows a date on both ends of its range, so a multi-day stay reads the same on every day it covers.
- **Patient documents** - Double-clicking 'Add' no longer creates duplicates.
- **Admin panel** - Fixes to the 'View default settings' modal and to several report and settings editor issues.

## Mobile

- Dates before 1970 can be entered, the administered vaccine table refreshes after an edit, program form lists load faster, and sync session errors are reported to central.

## System

- **Sync** - An unreachable sync process is reported as such rather than a generic fetch failure, and facilities record their sync credentials without needing central reachable.
- **Reports** - Central refuses report writes when reporting schemas fail to initialise.

# ⚠️ Critical Upgrade Notes

### Required

**_Configuration moved into settings_**

- Existing configuration migrates automatically. Review the settings in the admin panel afterwards to confirm they came across as expected.
- Changing a high-risk setting now requires full administrative permission. Confirm the right people hold it.
- Configuration files are still read as a fallback, so do not remove them as part of this upgrade.

**_Sync lookup rebuild_**

- The central upgrade now performs a full sync lookup rebuild as its final step and will not complete while the table is inconsistent. Allow extra time for large databases.

### Optional

**_'Send to pharmacy'_**

- The pharmacy fields appear only where the pharmacy order setting is enabled. Decide whether your deployment adopts this workflow.

**_Lab requests_**

- Two settings control priority handling, and both ship set to preserve current behaviour. Change them only if you want a priority to be required when a request is created, or locked once it has been submitted.
- Out-of-range flags rely on reference ranges configured against lab test types. Tests without a range are not flagged.

---

## Upgrade Steps and Recommended Testing

### Required

- Spot-check migrated settings against your previous configuration, particularly mail, integrations and scheduled tasks.
- Rehearse the upgrade against a copy of a production-sized database. The sync lookup rebuild runs as the final step and adds to the window.

### Optional

- If adopting 'Send to pharmacy', discharge a patient with both encounter and ongoing medications and confirm the right ones are ticked to send.

### General

- Confirm existing workflows still behave as expected.

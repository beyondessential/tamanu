Tamanu&nbsp;v2.67 is a smaller release. It moves patient record import and export into a 'Patient
data' view in the admin panel, adds 'Patient type' to emergency encounters, and shows stock in the
'Send to pharmacy' modal.

---

# 🔧 System enhancements

- **Patient data view** - Patients and administered vaccines are imported and exported through a new
  'Patient data' view in the admin panel, separate from reference data. The spreadsheet format and
  the test import are as before. Before an import runs, a confirmation explains that it creates new
  records and overwrites matching patient data, and cannot be undone.
- **Patient type on emergency encounters** - The 'New emergency triage' form has a 'Patient type'
  field, filled in from the patient's details where one is recorded, and price lists set up for a
  patient type apply to the emergency encounter. Changing it on the form does not change the
  patient's details. The encounter's details show its patient type, which can be changed through
  'Edit encounter details' and carries through when the patient is admitted to hospital.
- **Stock when sending to pharmacy** - The 'Send to pharmacy' modal has a 'Stock' column showing
  whether each medication is in stock at the facility, matching the 'Dispense medication' modal.
  Hovering over an in-stock medication shows the quantity on hand. Stock is for information only and
  does not stop a medication being sent.
- **Longer form logic** - Program form questions accept longer visibility criteria and calculations,
  so complex conditions no longer hit a length limit.
- **Database interruptions** - Servers stay up through a brief loss of their database connection,
  such as a database failover, and carry on once it returns rather than shutting down and
  restarting. A server only stops if the outage lasts several minutes.
- **Sync history** - Facility servers keep a record of every sync attempt and its outcome, so
  monitoring can pick up a sync that hangs as well as one that fails.

# 🐛 Tweaks and bug fixes

## Desktop

- **Encounters** - 'Patient type' is filled in when admitting from triage or from a referral.
  Editing an emergency encounter refuses an arrival or triage time in the future.
- **Patients** - The duplicate NHN check when editing a patient ignores capitalisation. Recording a
  death with an empty contributing condition row saves without it. A patient removed from a program
  registry can be registered again.
- **Medications** - A medication marked unavailable at the facility shows 'Unavailable' stock rather
  than 'Unknown'. Users without permission to see the medication administration record or not
  dispensed details see a message rather than a blank page.
- **Labs and imaging** - Clearing 'Date & time collected' clears the sample details recorded with
  it. Changing the imaging type clears 'Areas to be imaged'.
- **Invoicing** - Saving a procedure no longer overwrites changes the cashier has made to the
  invoice. An insurance plan, lab test or lab panel with every facility removed from it is offered
  at all facilities, where before it was offered at none. Clearing an invoice item's quantity no
  longer causes an error.
- **Vitals and charts** - Editing a recorded value no longer fails where the chart includes a
  question showing the patient's previous answer.
- **Admin panel** - The reference data 'Manage' tab checks permissions for each data type, applies
  the same code and id rules as the import, enforces required fields when editing, and saves an
  optional number field once it is cleared. Drug routes are checked on import. Vaccine consent
  import and export are tightened, and re-importing an exported administered vaccines sheet keeps
  the vaccines' encounters and circumstances.

## Mobile

- **Sync** - Saving pulled data during sync is faster.
- **Patients** - A patient with no recorded allergies shows 'None recorded'.

## System

- **Integrations** - FHIR medication requests carry the dispense quantity in the standard format.

## Upgrade steps and recommended testing

### Required

**_Patient type_**

- Create an emergency encounter for a patient with a patient type recorded. Confirm the field is
  filled in, then admit the patient to hospital and confirm the patient type carries over.

### Optional

**_General_**

- Upgrade an existing Tamanu Mobile device, record some data and sync. Confirm the sync completes
  and the new records appear on Tamanu Desktop.

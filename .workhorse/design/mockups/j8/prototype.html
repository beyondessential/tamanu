Medication / Dispensing / Sending to pharmacy

Sending medications to pharmacy

How to send prescribed medications to pharmacy at prescribing and at discharge.

Medications can be sent to pharmacy at the two points where prescribing happens: when writing a new prescription, and when discharging a patient. Sending a medication creates a pharmacy order so it can be dispensed and tracked.

Before you start

The pharmacy fields appear only where the pharmacy order setting is enabled for your facility. If you do not see them, ask your administrator.

Sending when prescribing

When you write a new prescription, you can send it to pharmacy in the same step.

  1. Open the patient's encounter and select New prescription.
  2. Complete the medication details as usual.
  3. Turn on Send to pharmacy. It is off by default.
  4. Enter a Dispensing quantity, then save the prescription.

Sending at discharge

At discharge, the patient's encounter medications are ticked to send by default, so routine discharge medications go to pharmacy without extra steps.

  • The Discharge modal shows a Send to pharmacy column, ticked for encounter medications and unticked for other ongoing medications.
  • Stock on hand, when a request was last sent, and whether it is still active or already dispensed are shown while you decide.
  • Dispensing quantity must be filled in for each medication being sent.

Tracking a sent medication

Once sent, a medication appears in the pharmacy's queue. The prescription record shows its status as it moves from ordered to dispensed.

Release notes

What changed in each version of Tamanu, with upgrade notes and recommended testing. Sourced from the release notes in GitHub.

v2.63Released 03-09-2026

Tamanu v2.63 is a small release, made up of enhancements and fixes rather than new features. Vaccination certificates can show a patient's birth certificate number, patient lists gain sortable columns, and deployments that report to DHIS2 can mark datasets complete when they are posted.

🔧 System Enhancements

  • DHIS2 dataset completion - For deployments that report to DHIS2, report data is pushed as datasets and each configured dataset is marked complete when it is posted. The DHIS2 dataset is set against a report through the report admin panel.

🐛 Tweaks and Bug Fixes

Desktop

  • Medications - All medication preset labels load rather than only the first 25, and the 'Medication administration schedule' section is collapsed by default in the medication form.
  • Surveys and charts - Large numeric answers display without being rounded.
  • Patients and dashboard - The encounter refreshes after a death is recorded, and the current day's appointment and booking panes fill in even when tasking is turned off.
  • Vaccination certificates - A new 'Display birth certificate number' flag under the 'Vaccinations' settings shows the patient's recorded birth certificate number in the patient details section of the certificate. It is off by default, and the field is left empty where no number has been recorded.
  • Patient lists - Additional columns on the patient listings, including Area and Location, can now be sorted, making it easier to find patients in a long list and organise a working patient list.
  • Imaging - 'X-ray (Portable)' is added as an imaging type.

Mobile

  • The vitals 'Add' tab submits correctly after a prior submission, and query performance is improved through additional database indexes and periodic refreshing of query statistics. The Android build is updated to support devices with 16 KB memory pages.

System

  • Reports - Soft-deleted survey responses are excluded from the generic survey export.

⚠️ Critical Upgrade Notes

Optional

Vaccination certificate birth certificate number

  • The birth certificate number is off by default. Enable 'Display birth certificate number' under the 'Vaccinations' settings if you want it on the certificate.
  • The number is drawn from patient details, so it appears only for patients who have one recorded.

Portable X-ray

  • Add 'X-ray (Portable)' to your list of imaging types via admin panel settings.

Upgrade Steps and Recommended Testing

Optional

Vaccination certificate

  • If enabling the birth certificate number, generate a certificate for a patient who has one recorded and confirm it appears.
v2.62Released 17-08-2026

Tamanu v2.62 is a modest release. Its main change is administrative: a large amount of server configuration moves into the admin panel. Clinically, the 'Send to pharmacy' workflow extends to discharge and prescribing, and lab requests gain out-of-range result flags.

🌟 Major Features and Changes

System Administration

Configuration Managed in the Admin Panel

Configuration that previously lived in files on each server is now database-backed settings, editable in the admin panel with validation and per-facility overrides. Existing values migrate automatically during the upgrade, so nothing needs re-entering and behaviour does not change.

Key features

  • Editable without server access - Mail, scheduled tasks, integrations, localisation, reporting and rate limiting are managed in the admin panel.
  • Carried across on upgrade - Existing configuration migrates automatically, and a value already set in settings is never overwritten.
  • Applied without a restart - A saved setting takes effect on the next read, and the few that need a restart are marked.
  • High-risk settings protected - Changing one now requires full administrative permission, enforced by the server.
  • Integration credentials encrypted - Secrets use one deployment-wide key, generated by central and distributed to facilities over sync, so no key needs placing on a server by hand.

Tamanu Desktop

'Send to Pharmacy' from Discharge and Prescribing

Medications can now be sent to pharmacy at the two points where prescribing happens: writing a new prescription, and discharging a patient. At discharge the patient's encounter medications are ticked to send by default, with stock and previous requests visible while deciding.

Key features

  • At discharge - A 'Send to pharmacy' column on the 'Discharge' modal, ticked for encounter medications and unticked for other ongoing medications.
  • When prescribing - A 'Send to pharmacy' option on the 'New prescription' modal, off by default.
  • Dispensing quantity required - 'Discharge qty' becomes 'Dispensing qty' and must be filled in.
  • Stock and history in view - Columns show stock, when a request was last sent, and whether it is still active or already dispensed.

The pharmacy fields appear only where the pharmacy order setting is enabled.

Supporting documentation

  • Feature overview - [SLAB_LINK_PLACEHOLDER]
  • User manual - [SLAB_LINK_PLACEHOLDER]

🔧 System Enhancements

  • Lab request result flags - An individual 'Lab request' now highlights numeric results outside their reference range, matching the patient-level results table, with a tooltip naming the bound breached. Fields edited after entry carry an asterisk and a legend below the table.
  • Lab request priority - Two settings control whether a priority must be chosen when a request is created, and whether it can be changed afterwards. Both default to current behaviour.
  • Vitals and charting time ranges - Last 7 days, last 30 days and last year are available at the encounter level and for program registry charts.
  • Sync lookup self-healing - The central sync lookup table now repairs rows whose source changed without advancing the sync clock, which is what happens during a migration. Healed rows keep their sync tick, so facilities do not re-download records they already hold.
  • Hard deletes in the audit changelog - A permanently removed row is now recorded as it stood before removal and marked as a hard delete. Changelog writing and its attachment to sync are also more memory-efficient.

🐛 Tweaks and Bug Fixes

Desktop

  • Invoicing - 'Details' and 'Ordered by' are now required on every line, so clearing 'Details' no longer silently deletes it. The reason for a discount or mark-up is visible on the item row, and a stale sliding fee discount no longer survives a change of family size.
  • Medications - The 'View patient' link opens the 'Patient summary' tab, the dispensed medication popup shows the medication actually dispensed, and 'Discontinued by' defaults to the current user.
  • Charts - Edit-history timestamps display in local time.
  • Scheduling - A booking running past midnight shows a date on both ends of its range, so a multi-day stay reads the same on every day it covers.
  • Patient documents - Double-clicking 'Add' no longer creates duplicates.
  • Admin panel - Fixes to the 'View default settings' modal and to several report and settings editor issues.

Mobile

  • Dates before 1970 can be entered, the administered vaccine table refreshes after an edit, program form lists load faster, and sync session errors are reported to central.

System

  • Sync - An unreachable sync process is reported as such rather than a generic fetch failure, and facilities record their sync credentials without needing central reachable.
  • Reports - Central refuses report writes when reporting schemas fail to initialise.

⚠️ Critical Upgrade Notes

Required

Configuration moved into settings

  • Existing configuration migrates automatically. Review the settings in the admin panel afterwards to confirm they came across as expected.
  • Changing a high-risk setting now requires full administrative permission. Confirm the right people hold it.
  • Configuration files are still read as a fallback, so do not remove them as part of this upgrade.

Sync lookup rebuild

  • The central upgrade now performs a full sync lookup rebuild as its final step and will not complete while the table is inconsistent. Allow extra time for large databases.

Optional

'Send to pharmacy'

  • The pharmacy fields appear only where the pharmacy order setting is enabled. Decide whether your deployment adopts this workflow.

Lab requests

  • Two settings control priority handling, and both ship set to preserve current behaviour. Change them only if you want a priority to be required when a request is created, or locked once it has been submitted.
  • Out-of-range flags rely on reference ranges configured against lab test types. Tests without a range are not flagged.

Upgrade Steps and Recommended Testing

Required

  • Spot-check migrated settings against your previous configuration, particularly mail, integrations and scheduled tasks.
  • Rehearse the upgrade against a copy of a production-sized database. The sync lookup rebuild runs as the final step and adds to the window.

Optional

  • If adopting 'Send to pharmacy', discharge a patient with both encounter and ongoing medications and confirm the right ones are ticked to send.

General

  • Confirm existing workflows still behave as expected.
v2.61Released 10-08-2026

Tamanu v2.61 brings automatic invoicing of encounter, bed and inpatient fees, so facilities no longer add routine charges by hand. It also delivers a substantial set of medication improvements: pharmacy can now modify a prescription at the point of dispensing, and dispensing quantities can be calculated automatically from the prescription. Encounter notes gain search and filtering, and the 'Emergency patients' board gains filters and a clinician column.

🌟 Major Features and Changes

Tamanu Desktop

Automatic Encounter, Bed and Inpatient Fees

Routine charges are now added to invoices automatically as care happens. An outpatient or emergency fee is applied when a visit starts, admitted patients accrue a bed fee for each night, and facilities that bundle clinical items into their admission fee can stop those items being billed twice. Every amount comes from the existing price list system, so there is one pricing mechanism to learn and a facility manages a single price list.

Key features

  • Outpatient and emergency fees - A fee is added once when the encounter starts, with the amount chosen by the time of day: standard hours, weekday after hours, or weekend. Emergency encounters (triage, active ED, and emergency short stay) are charged their own set of fees.
  • Separate emergency hours - The emergency in-hours window is configured separately from the outpatient window, so a state can run different ED hours. A facility that does not distinguish weekend ED care can leave the weekend product unpriced and it falls back to the after-hours rate.
  • Per-night bed fee - Admitted patients are charged the first night on admission, then one night per overnight check while they remain admitted. Each chargeable bed or ward is priced individually, so rates can differ between ICU and a general ward. The invoice shows one line per location with the number of nights as the quantity.
  • Walk-in pharmacy fee - A dedicated flat fee for walk-in pharmacy dispensing visits. Charging pharmacy is opt-in: price the product and the fee applies, leave it unpriced and no fee line appears.
  • Inpatient fee bundling - Facilities can nominate which categories (imaging, lab, medications) are covered by the admission fee and should not be itemised separately on an admission invoice. Outpatient and emergency encounters continue to invoice every category, and procedures always invoice separately.
  • Fees behave like manual items - A cashier can adjust or remove an automatic fee, for example on a public holiday, and a removed fee is not re-added on a later re-run or sync.

Prescription Modification at Dispensing

Pharmacy can now change the details of a prescription while dispensing it, without sending it back to the prescriber. Where the exact stock is not on hand, pharmacy can dispense an available strength or formulation and record what was actually given, along with a reason. The original prescription is left intact and the prescriber is notified of the change, so the clinical record reflects both what was ordered and what the patient received.

Key features

  • Modify prescription during dispensing - A 'Modify prescription' option on the 'Dispense medication' modal opens the prescription for editing, including changing to or from a variable dose.
  • Reason for modification captured - Every modification records a reason from a configurable list, along with the user who made it.
  • Original prescription preserved - Changes apply to the dispensing record only, so the prescriber's original intent remains on the record.
  • Prescriber notified - A pharmacy note is added to the original prescription and the prescriber receives a notification on their clinician dashboard, where they can see what changed.
  • Modified medications flagged - Modified items are marked with an asterisk in the dispensed medication tables, with a 'View modify history' option showing the original and current prescription side by side.
  • Visible on the MAR - The pharmacy note and a 'View change' action appear on the medication administration record.

Medication Dispensing Quantity Autocalculation

Tamanu can now work out the dispensing quantity from the dose, frequency and duration of a prescription, so the quantity no longer has to be counted out by hand. The calculated figure is a starting point rather than a lock, and pharmacy or the prescriber can overwrite it before finalising. This removes a common source of arithmetic error between prescribing and dispensing.

Key features

  • Automatic quantity on prescribing - The dispensing quantity fills in from dose, frequency and duration as the prescription is written.
  • Expressed in dispensing units - Quantities are given in the units the medication is handed out in, such as packs or bottles, using each drug's conversion factor.
  • Ongoing medications default to a month - Medications marked ongoing calculate a 30 day supply, and one month always counts as 30 days.
  • Manual entry is respected - Once a user enters their own quantity, later edits to the prescription no longer overwrite it. Changing the medication resets the calculation.
  • Left blank where it cannot be inferred - A variable dose, an 'As directed' frequency, a duration in hours, or no duration on a non-ongoing medication all leave the field empty for manual entry.
  • Covers medication sets and dispensing edits - Quantities are calculated for each drug in a medication set, and recalculated when a prescription is modified during dispensing.

Encounter Notes Search and Filters

Clinical notes on an encounter can now be searched and filtered instead of scrolled through. A clinician looking for earlier notes on a specific topic can type a word or phrase and narrow by note type, author, or date range. This was raised by rehabilitation clinicians who needed to compare a patient's progress notes over time without reading the whole history.

Key features

  • Free text search of note content - Type a word or phrase to show only notes containing it.
  • Results update as you type - There is no search button. The free text box applies after a short pause and the other filters apply immediately.
  • Filter by note type and author - The author filter matches whoever wrote the note and anyone who later edited it, including edits made on behalf of another user.
  • Date range in 'Advanced search' - Set a from date, a to date, or just one. An open-ended boundary returns everything up to today or back to the first note.
  • Treatment plan stays pinned - Newest first ordering is preserved and the 'Treatment plan' note remains at the top when it matches the filters.
  • One-click clear - A 'Clear' action resets every filter at once.

'Emergency Patients' Board Enhancements

The 'Emergency patients' board gains search filters and a clinician column, so emergency department staff can cut a long waiting list down to the patients they are responsible for. Several display changes make the board easier to read at a glance. This addresses feedback that clinicians were avoiding moving patients into active ED care because acuity became less visible once they did.

Key features

  • Search and clinician filter - Filter the board by patient ID, first name or last name, or narrow it to one clinician's patients.
  • Advanced filters - Filter by triage category, area and location. Triage category options come from the deployment's own configured categories, and a location can only be chosen once its area is selected.
  • Filters persist across navigation - Leaving the board and returning keeps your filters, matching the other patient listing pages.
  • Clinician column - A sortable clinician column, with a tooltip where the name is too long to display in full.
  • Clearer display - Grey tiles for patients already seen now state whether they moved to 'Active ED' or 'Emerg. short stay', and the sex column shows M, F or O rather than the full word.
  • Refreshed default triage colours - The Urgent, Non-urgent and Deceased categories use new default colours with better contrast, and remain fully configurable.

🔧 System Enhancements

Reference Data Search in the Admin Panel

Searching reference data by ID in the admin panel now matches on the ID rather than the record name, so administrators can find a record using the identifier they already have.

🐛 Tweaks and Bug Fixes

Desktop

  • Invoicing - Payment corrections, including the total due when a payment is edited to $0 and refunds netted out of the remaining balance on printed invoices.
  • Medications - Dispensing corrections across labels, pharmacy notes and preset label loading. Administration records can no longer be edited after discharge.
  • Tasks - Text size, column width and alignment corrections across the task tables.
  • Labs - Historical categories and panels a patient has results for are now shown, plus fixes to results entry and display.
  • Patients and encounters - Fixed duplicate patient creation, triage wait time calculation, and 'Place of death' on certificates for deaths outside a facility. 'Record death' now requires patient write access.
  • Forms, charts and programs - Corrections to question rendering, validation and changelog display in the 'Charts' tab and program registries.
  • Reports and imaging - Report parameters clear correctly, load failures show a readable message, and saving an imaging request no longer creates a blank result.
  • General - More reliable table loading and error states, correct handling of special characters in translation search, and accessibility improvements to buttons and required-field markers.

Mobile

  • Dates and times - Dates before 1970 can now be entered, and midday, midnight and day boundaries display in the correct local time.
  • Surveys and program registration - Submissions roll back on error rather than saving partial data, and registration date and mandatory field handling are corrected.
  • Performance - Program form lists load faster.
  • Authentication and sync - Offline login and sign-out behaviour corrected, along with several sync data integrity fixes.

System

  • Sync - Large sync batches no longer exhaust memory during the persist phase, sensitive facility data no longer reaches other facilities, and sync is no longer blocked when creating a new facility.
  • FHIR - Survey response encounters are now materialised, and several job processing issues are resolved.
  • Central and facility servers - Reliability improvements to scheduled tasks, report generation and bookings, plus tighter permission enforcement on sensitive labs.
  • Settings and data - Timezone handling corrections and faster, more resilient database migrations.

⚠️ Critical Upgrade Notes

Required

'Emergency patients' board

  • Default triage category colours have changed for Urgent, Non-urgent and Deceased. Deployments on the defaults will see the board change colour after upgrade; those that have customised their triage colours are unaffected. Review and customise if your states expect the previous colours.

Prescription modification at dispensing

  • Set up the modification reason list with the reasons your pharmacy teams should choose from. Pharmacy cannot record a modification until this exists.
  • Review which staff can dispense medications, as that permission now also allows modifying a prescription during dispensing.

Optional

Automatic encounter fees

  • Invoicing remains off by default. Decide whether your deployment adopts encounter fees this release.
  • If adopting, plan the reference data and price list work with your project manager: the encounter fee products, an optional walk-in pharmacy fee, and a bed fee product for each chargeable location. See the configuration guide for the setup.
  • Decide the per-facility settings each state needs: the standard-hours windows for outpatient and emergency, the overnight bed fee check time, and which item categories are bundled into the inpatient fee.

Medication dispensing quantity autocalculation

  • Off by default. Decide whether to enable it per deployment.
  • Before enabling, check that the dispensing unit conversion is filled in on your medication reference data. Where it is left unset, quantities calculate in dosing units rather than packs or bottles.

Upgrade Steps and Recommended Testing

Required

Prescription modification at dispensing

  • Configure the modification reason reference data and confirm the options suit your pharmacy team.
  • Test the full workflow: modify a prescription during dispensing, confirm the original prescription is unchanged, and confirm the prescriber receives the pharmacy note notification.
  • Confirm the modified item is flagged in the dispensed medication tables and that 'View modify history' shows the original and current details.
  • If your deployment uses the mSupply integration, verify it sends the medication that was actually dispensed rather than the original prescription.

'Emergency patients' board

  • Review the refreshed triage colours on the 'Emergency patients' board and confirm they suit your deployment, or customise them to keep your existing colours.

Optional

Automatic encounter fees

  • Test in a non-production environment first. Fee behaviour depends on reference data and price lists being set up correctly.
  • Confirm the correct fee is applied for an outpatient visit in standard hours, after hours, and on a weekend, and likewise for an emergency encounter.
  • Confirm a patient admitted from ED keeps the ED fee and is also charged the first bed-fee night on the same invoice.
  • Admit a patient across several nights and confirm the invoice shows one line per location with the correct number of nights.
  • Where inpatient bundling is configured, confirm bundled items do not appear on an admission invoice but still appear on outpatient and emergency invoices, and that discharge medications are still billed.
  • Confirm a cashier can adjust or remove an automatic fee, and that it is not re-added on a later sync.

Medication dispensing quantity autocalculation

  • Fill in the dispensing unit conversion for your medication reference data, then confirm calculated quantities come out in packs or bottles as expected.
  • Confirm a manually entered quantity is not overwritten by later edits to the prescription.
  • Confirm the quantity is left blank for a variable dose, an 'As directed' frequency, and a duration in hours.

Encounter notes search

  • Test free text search, note type, author and date range filters against a patient with a long note history.
  • Confirm the treatment plan stays at the top of the list when it matches the filters.

General

  • Test all bug fixes mentioned in the release notes.
  • Verify that existing workflows continue to function as expected.

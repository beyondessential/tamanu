18. Labs

Lab requests, test and panel selection, sample collection, results, and access to sensitive tests.

These guides step system administrators through the set up of the Tamanu Labs Module.

18.1Reference data

The reference data the Tamanu Labs Module needs, and the values each column accepts. The tests and panels staff order, and the options they choose from when requesting and processing a lab, are all reference data. Reference data is configured through the reference data import spreadsheet, downloaded from and uploaded to your Tamanu system. Records can also be added and edited one at a time on the Manage tab of the Reference data screen in the admin panel.

iNote

The Manage tab is supported from v2.54 onwards. Earlier deployments configure reference data by import spreadsheet only.

For the settings that govern lab requests see Settings, and for the permissions required see Permissions.

Reference Data Types

See the Tamanu Reference Data Manual for how importing works. The Labs reference data template has a tab for each type below.

Tab names are matched without regard to case or plurals, so Lab Test Category and Lab Test Categories both import as lab test categories.

Lab Test Category

Lab test categories, also known as lab departments, group lab test types and panels. When creating a lab request, tests and panels are listed under their category.

Screenshot needed

the new lab request test selector, with tests grouped by category

Field Value
Tab name Lab Test Category

Where * is a required field.

Column name Description
id * Unique id for the category. Letters, numbers and hyphens only.
code * Unique code for the category. Letters, numbers, hyphens, full stops and forward slashes only.
name * The category name displayed in Tamanu.
visibilityStatus current for categories in use, or historical for categories that should no longer appear. Defaults to current if blank.
availableFacilities Does not restrict which tests can be ordered at a facility. Set availableFacilities on the Lab Test Types and Lab Test Panels instead, and leave this blank.
defaultSpecimenType The specimen type filled in by default when recording a sample for tests in this category (supported from v2.66 onwards). Must be the id of a Specimen Type, not its name; an unrecognised id fails the import. Staff can still change the specimen type when recording the sample. Leave blank for no default.

The defaultSpecimenType column changes existing data in two ways on import:

  • A blank cell removes the category's existing default specimen type
  • A sheet without the column leaves every category's existing default unchanged

An export writes the specimen type id back, so an exported sheet re-imports unchanged.

Lab Test Type

Lab test types are the individual tests available for your deployment, either to order on their own or as part of a panel.

Field Value
Tab name Lab Test Type

Where * is a required field.

Column name Description
id * Unique id for the test. Letters, numbers and hyphens only.
code * Unique code for the test.
name * The test name displayed when ordering and on results.
unit The unit of measure displayed with a result, for example mg/dL. Leave blank if the result has no unit.
maleMin The minimum of the normal range for male patients, as a number. A Number result below it is flagged as outside the normal range. Leave blank for no minimum.
maleMax The maximum of the normal range for male patients, as a number. A Number result above it is flagged as outside the normal range. Leave blank for no maximum.
femaleMin The minimum of the normal range for female patients, as for maleMin.
femaleMax The maximum of the normal range for female patients, as for maleMax.
rangeText The normal result as text, for example Negative, for tests without a numeric range. Any result that does not match it exactly is flagged as outside the normal range. Only used where no numeric range is set for the patient's sex. Leave blank for no normal result.
resultType * How a result is entered. One of the values listed under Result types.
options The choices for a Select result, separated by a comma and a space, for example Positive, Negative, Inconclusive. Leave blank for other result types.
isSensitive Input TRUE to make the test sensitive, so only users with the required permissions can see or order it. Defaults to non-sensitive if blank. See Sensitive labs.
supportsSecondaryResults Input TRUE to add a second result column when entering results for this test (supported from v2.52 onwards). Defaults to a single result if blank.
visibilityStatus Whether and how the test can be ordered. One of the values listed under Lab test visibility. Defaults to current if blank.
availableFacilities Restricts the test to specific facilities when ordering. Must be a JSON array of facility ids, for example ["facility-a"]. Leave blank for all facilities.
externalCode The code sent to external systems such as a laboratory information system, for example a LOINC code. Leave blank if not used.
labTestCategoryId * The id of the test's Lab Test Category.
Screenshot needed

a result flagged as outside the normal range when entering results

A patient whose sex is not male or female has no numeric normal range, so their results are compared against rangeText only.

!Warning

Separate options with a comma and a space. Positive,Negative without the space is read as a single option. The importer does not require options for a Select test, so a Select test imported without them has nothing to choose from.

For a Select test, set rangeText to the normal option exactly as it is written in options, so only abnormal results are flagged.

Lab Test Panel

Lab test panels group lab test types that are commonly ordered together, so staff can order them in one step. If no panels are configured, staff order individual tests only.

Field Value
Tab name Lab Test Panel

Where * is a required field.

Column name Description
id * Unique id for the panel. Letters, numbers and hyphens only.
code * Unique code for the panel.
name * The panel name displayed when ordering.
visibilityStatus current for panels that can be ordered, or historical for panels that should no longer appear. Defaults to current if blank.
externalCode The code sent to external systems such as a laboratory information system. Leave blank if not used.
availableFacilities Restricts the panel to specific facilities. Must be a JSON array of facility ids. Leave blank for all facilities. Tests in the panel that are not available at a facility are left out when the panel is ordered there.
categoryId * The id of the panel's Lab Test Category. It must be an id, not a name.
testTypesInPanel The ids of the Lab Test Types in the panel, separated by commas. Tests display in the order they are listed. A panel with this column blank contains no tests.

A panel's tests must meet these rules, and an import that breaks them fails:

  • All tests belong to the same category (supported from v2.66 onwards)
  • No test is a reflex test (supported from v2.66 onwards)
  • No test is sensitive

The importer checks that a panel's tests share a category, but not that it is the same category as the panel's categoryId, so keep the two in line.

!Warning

Setting a test to historical stops it being ordered on its own, but panels that already list it still order it. Remove a retired test from testTypesInPanel as well.

Hard coded fields

The values these fields accept are fixed. Changing them requires a code change, requested through your system administrator or project manager.

Result types

The values resultType accepts:

Value Result entry
Number A number, flagged when outside the normal range
Select A choice from the test's options
FreeText Any text

Lab test visibility

The values a lab test type's visibilityStatus accepts:

Value Displays as Ordering
current Current Ordered on its own or in a panel
historical Historical No longer ordered on its own; still ordered by panels that list it
panelOnly Panel only Ordered only as part of a panel
reflexTest Reflex test Never ordered. Exists so a laboratory information system can add its result to a request (supported from v2.66 onwards)

Panels and the other lab reference data accept current and historical only.

Cancellation reasons

The reasons offered when cancelling a lab request. The reason chosen decides the request's new status, and a note recording it is added to the request.

Field Value
Scope Global (All Facilities/Servers)
Category None. Shown when no category is selected
Sub-category None
Setting Labs cancellation reasons
Default Clinical reason, Duplicate, Entered in error, Patient discharged, Patient refused, Other
Screenshot needed

the Cancel lab request window, listing the cancellation reasons

Reason value Request status
duplicate Deleted
entered-in-error Entered in error
Any other Cancelled

Required format: a list of reasons, each with a value stored against the request and a label displayed to staff. A value must be lower case and at most 31 characters.

[
  { "value": "clinical", "label": "Clinical reason" },
  { "value": "duplicate", "label": "Duplicate" },
  { "value": "entered-in-error", "label": "Entered in error" },
  { "value": "patient-discharged", "label": "Patient discharged" },
  { "value": "patient-refused", "label": "Patient refused" },
  { "value": "other", "label": "Other" }
]

The list must keep reasons with the values duplicate and entered-in-error. Saving a list without them shows one of these errors:

  • labsCancellationReasons must include an option with value = duplicate
  • labsCancellationReasons must include an option with value = entered-in-error

Labels can be changed freely.

Automatic lab test result publisher supported from v2.62 onwards

iNote

Before v2.62, the result publisher is set in the central server's configuration file. Contact your system administrator to change it.

Publishes a result automatically for point-of-care tests, such as rapid antigen tests, whose result is known when they are ordered. Each run, the central server finds tests of the configured types that have no result and whose request is Reception pending. It sets the configured method and result, sets the completed date to the requested date, and publishes the request.

Field Value
Scope Central (Sync server)
Category Scheduled tasks
Sub-category Automatic lab test result publisher
Setting Enabled, Schedule, and Results
Default Disabled, every 15 minutes

Required format for Results: each lab test type id maps to the id of a Lab Test Method and the result to record. The default maps two rapid antigen test types:

{
  "labTestType-RATPositive": { "labTestMethodId": "labTestMethod-RAT", "result": "Positive" },
  "labTestType-RATNegative": { "labTestMethodId": "labTestMethod-RAT", "result": "Negative" }
}

Changes take effect after the central server restarts.

!Warning

The whole lab request is published, including any other tests ordered with a configured test. Only configure test types that are ordered on their own.

Sync all lab requests

Syncs every lab request in the deployment, with its encounter, to a facility, rather than only those for patients the facility already syncs. Use it for a facility that processes samples for other facilities, such as a central laboratory.

Field Value
Scope Facility (Single Facility)
Category Sync
Sub-category None
Setting Sync all lab requests
Default Disabled
!Warning

This is a high risk setting. It can greatly increase the data a facility syncs, so turn it on only for the facility that needs it.

18.3Permissions

The permissions that control who can request labs, record samples and results, change a request's status, and access sensitive tests in the Tamanu Labs Module.

For the reference data these permissions act on see Reference data, and for the module's settings see Settings.

Permissions

See the Users configuration guides for more detail on roles and permissions in Tamanu.

Lab requests

Required to view, create and update lab requests:

  • list for LabRequest
    • View the Active requests and Finalised lab request lists
    • View the lab requests on an encounter's Labs tab
  • read for LabRequest
    • Open a lab request and view its tests and notes
    • Print lab requests from an encounter's Labs tab
  • write for LabRequest
    • Record sample details, and change the laboratory and priority
    • Add notes to a lab request
    • Without it, a lab request opens read only
  • create for LabRequest
    • Create a lab request with New lab request

Printing a sample label or a lab request from an open request needs no permission beyond opening it.

Status changes

Required to change a lab request's status and view its history:

  • write for LabRequestStatus
    • Change a lab request's status, including cancelling it. Also needs write for LabRequest
  • list for LabRequestLog
    • View a lab request's status history

Tests and results

Required to view and enter results:

  • list for LabTest
    • View the tests on a lab request
  • read for LabTest
    • View a test and its result history
  • write for LabTest
    • Enter results, and record a test's method, completed date and verification
  • read for LabTestResult
    • View the patient Results tab
    • Print results and interim reports, where the Lab results printout setting is enabled
  • write for LabTestResult
    • Record and change result values. Without it, results open read only

Entering results needs write for both LabTest and LabTestResult.

Ordering tests and panels

Required to choose what to order on a lab request:

  • list for LabTestType
    • Choose individual tests when creating a lab request
  • list for LabTestPanel
    • Choose panels when creating a lab request
  • read for LabTestPanel
    • View a single panel's details

Lab reference data

Importing and exporting lab reference data is controlled by the type being imported:

Reference data Import Export
Lab Test Type create and write for LabTestType list for LabTestType
Lab Test Panel create and write for LabTestPanel list for LabTestPanel
Lab Test Category, Specimen Type, Lab Test Priority, Lab Sample Site, Lab Test Laboratory, Lab Test Method create and write for ReferenceData list for ReferenceData

The Manage tab of the Reference data screen checks ReferenceData for every type, including lab test types and panels. A role that imports lab test types still needs write for ReferenceData to edit them on the Manage tab.

Permissions for sending lab requests to and receiving results from a laboratory information system are covered in the Integrations configuration guides.

Permissions with no effect

These are listed in the permissions admin panel, but granting them changes nothing:

  • read, write and create for LabRequestLog
  • create for LabTest. Tests are created with their lab request
  • list for LabTestResult
  • read for LabTestType

Sensitive labs supported from v2.37 onwards

A lab test type can be marked as sensitive, so only users with the permissions below can see, order or update it. Mark a test as sensitive by inputting TRUE in its isSensitive column; see Lab Test Type.

Sensitive tests follow these rules, and an import that breaks them fails:

  • A lab test category holds either sensitive or non-sensitive tests, never both. The import shows Cannot add sensitive lab test type to non sensitive category '<category id>', or the reverse
  • A panel cannot contain a sensitive test. The import shows Lab test panels cannot contain sensitive lab test types

Required to view, update and order sensitive labs. Each applies to lab requests that include a sensitive test, alongside the matching LabRequest permission:

  • list for SensitiveLabRequest
    • View sensitive lab requests in the Active requests and Finalised lists, on an encounter's Labs tab, and on the patient Results tab. Without it, they are hidden, with no message
  • read for SensitiveLabRequest
    • Open a sensitive lab request and view its tests and results
  • write for SensitiveLabRequest
    • Record sample details, enter results, add notes and change the status of a sensitive lab request
  • create for SensitiveLabRequest
    • Order sensitive tests. Without it, sensitive tests are not offered when creating a lab request
!Warning

Marking an existing test as sensitive can affect Tupaia visuals and mSupply integration. Contact the Tupaia and mSupply support teams to discuss the impact first.

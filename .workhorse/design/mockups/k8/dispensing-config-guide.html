16. Dispensing

Sending prescriptions to pharmacy, dispensing medications and printing their labels, and recording medications that cannot be dispensed.

These guides step system administrators through the set up of dispensing in Tamanu.

iNote

Dispensing is supported from v2.49 onwards.

# Guide Covers
16.1 Reference data Reasons for modifying or not dispensing a prescription, preset label wording, and the prescription types
16.2 Settings Sending prescriptions to pharmacy, automatic dispensing encounters, prescription labels, removing undispensed requests, and the sidebar
16.3 Permissions Sending prescriptions to pharmacy, dispensing, and managing dispensed medications

How dispensing works

  1. A prescriber sends prescriptions to pharmacy with Send to pharmacy, from an encounter's Medication tab, a new prescription, the discharge form, or the patient's ongoing medications
  2. Pharmacy staff see the request in Medication, then Active requests
  3. Opening a request shows Dispense medication, where staff record what is dispensed and print labels. A request that cannot be filled is recorded as Not dispensed
  4. Dispensed medications are listed in Medication, then Dispensed medications, and on the patient's Medication tab

16.1Reference data

The reference data dispensing needs, and the values each column accepts. The reasons and preset labels pharmacy staff choose from when dispensing are all reference data. Reference data is configured through the reference data import spreadsheet, downloaded from and uploaded to your Tamanu system. Records can also be added and edited one at a time on the Manage tab of the Reference data screen in the admin panel.

iNote

The Manage tab is supported from v2.54 onwards. Earlier deployments configure reference data by import spreadsheet only.

For the settings that govern dispensing see Settings, and for the permissions required see Permissions.

Reference Data Types

See the Tamanu Reference Data Manual for how importing works.

The medications that can be dispensed, and their stock levels, are configured in the Drug reference data. See Drug in the Medications guides.

Medication Preset Label supported from v2.57 onwards

Preset wording for the instructions printed on a medication label, such as "Take one twice daily". When dispensing, staff choose a preset by its code in the Preset labels column, and its wording replaces the Label text. Clearing the preset returns the label text to the wording built from the prescription.

Screenshot needed

the Preset labels column in Dispense medication

Field Value
Tab name Medication Preset Label

Where * is a required field.

Column name Description
id * Unique id for the preset. Letters, numbers and hyphens only.
code * The short code staff choose, such as BD. The Preset labels column shows and searches codes only, sorted by code. Letters, numbers, hyphens, full stops and forward slashes only.
name * The wording printed on the label, such as Take one twice daily.
visibilityStatus current for presets in use, or historical for presets that should no longer appear. Defaults to current if blank.
availableFacilities Restricts the preset to specific facilities. Must be a JSON array of facility ids, for example ["facility-a"]. Leave blank for all facilities.

The Preset labels column only appears where at least one preset is available at the facility.

Medication Dispense Modify Reason supported from v2.61 onwards

The reasons for modifying a prescription at the point of dispensing, such as "Out of stock" or "Substitution". Where the exact medication is not on hand, pharmacy can dispense an available strength or formulation through Modify prescription, and must choose a Reason for modification. The original prescription is left unchanged, and the reason appears in Modify prescription history.

Field Value
Tab name Medication Dispense Mod Reason

Where * is a required field.

Column name Description
id * Unique id for the reason. Letters, numbers and hyphens only.
code * Unique code for the reason. Letters, numbers, hyphens, full stops and forward slashes only.
name * The reason displayed in Tamanu.
visibilityStatus current for reasons in use, or historical for reasons that should no longer appear. Defaults to current if blank.
availableFacilities Not applied to these reasons, which show at every facility. Leave blank.

The tab name is shortened because spreadsheet tab names are limited to 31 characters. An import also accepts the tab named Medication Dispense Modify Reason.

Medication Not Dispensed Reason supported from v2.66 onwards

The reasons for recording a request as not dispensed, such as "Out of stock" or "Patient declined". Choosing Not dispensed on a request in Active requests opens Record medication as not dispensed, where a Reason for not dispensing is required. The request is removed from Active requests and the prescriber is sent a notification with the reason.

Field Value
Tab name Medication Not Dispensed Rsn

Same columns as Medication Dispense Modify Reason, including that availableFacilities is not applied. An import also accepts the tab named Medication Not Dispensed Reason.

Hard coded fields

The values these fields accept are fixed. Changing them requires a code change, requested through your system administrator or project manager.

16.2Settings

The settings that change how prescriptions are sent to pharmacy, how dispensed medications are labelled, and when undispensed requests are removed. Settings are managed in the Settings admin panel.

For the reference data these settings act on see Reference data, and for the permissions required see Permissions.

Settings

Settings are managed in the Settings admin panel. Every setting below works without configuration, using its default, except the automatic encounter location and department, which sending ongoing medications to pharmacy needs.

Sending to pharmacy

Pharmacy orders enabled

Shows Send to pharmacy on an encounter's Medication tab, on a new prescription, on the discharge form and on the patient's ongoing medications. When disabled, prescriptions cannot be sent to pharmacy. Staff also need create for MedicationRequest; see Permissions.

Dispensing outside an encounter

Sending a patient's ongoing medications to pharmacy, when the patient has no active encounter, creates a clinic encounter for the dispensing. These settings choose the location and department that encounter is recorded against. Set per facility.

Field Value
Scope Facility (Single Facility)
Category Medication
Sub-category Medication dispensing
Setting Automatic encounter location, and Automatic encounter department
Default None
!Required

Both must be set at every facility that sends ongoing medications to pharmacy. Without them, sending fails with an error that no automatic encounter location or department has been configured.

The automatic encounter department also decides the fee charged on these encounters. See the Invoicing configuration guides.

Requests sent to pharmacy that have not been dispensed are deleted automatically once older than the timeframe below. A scheduled task on the central server checks for them.

16.3Permissions

The permissions that control who can send prescriptions to pharmacy, dispense them, and manage dispensed medications.

For the reference data these permissions act on see Reference data, and for the settings that govern dispensing see Settings.

Permissions

See the Users configuration guides for more detail on roles and permissions in Tamanu.

The Medication sidebar menu shows for staff with read for either MedicationRequest or MedicationDispense. Staff with neither do not see it.

Sending to pharmacy

Required to send prescriptions to pharmacy, alongside the Pharmacy orders enabled setting:

  • create for MedicationRequest
    • Send to pharmacy from an encounter's Medication tab
    • Send to pharmacy on a new prescription and on the discharge form
    • Send to pharmacy from the patient's ongoing medications, when the patient has no active encounter

Sending also needs the medication permissions to view prescriptions; see the Medications permissions guide.

Active requests

Required to view and manage requests waiting to be dispensed:

  • read for MedicationRequest
    • View the Active requests screen
  • delete for MedicationRequest
    • Not dispensed, to record a request as not dispensed with a reason
    • Delete, to delete a request
    • Without it, the request actions menu is hidden

Dispensing

Required to dispense medications and manage dispensed records:

  • create for MedicationDispense
    • Open a request in Active requests and dispense it. Without it, requests cannot be opened
  • read for MedicationDispense
    • View the Dispensed medications screen
    • View the dispensed medications on the patient's Medication tab
  • write for MedicationDispense
    • Modify prescription while dispensing
    • Print label, Edit, Cancel and View modify history on a dispensed medication

Cancelling a dispensed medication needs write, not delete.

!Warning

On the patient's Medication tab, Edit and Cancel show on dispensed medications for staff without write for MedicationDispense, but fail when used. Print label works there without it.

Sensitive medications

Sensitive medications are set up in the Medications guides; see Sensitive medications. When dispensing:

  • list for SensitiveMedication
    • See sensitive medications in the dispensed medications on the patient's Medication tab
  • read for SensitiveMedication
    • Send a sensitive medication to pharmacy
    • See sensitive medications in Active requests, Dispensed medications and Dispense medication. Without it, they are hidden, with no message
    • Dispense a sensitive medication, including one chosen through Modify prescription
    • View the modify history of a sensitive medication

Permissions with no effect

These are listed in the permissions admin panel, but granting them changes nothing:

  • list and write for MedicationRequest
  • list and delete for MedicationDispense. delete was needed to delete a request before v2.66

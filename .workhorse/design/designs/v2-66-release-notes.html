Tamanu v2.66 release notes

Tamanu v2.66 reworks how lab requests are raised, sampled, labelled and resulted, so that panels and individual tests from one category become a single request and a single sample at the laboratory. It also introduces sensitive networks, which let a group of facilities share confidential data with each other, and lets pharmacy record a medication as not dispensed.

🌟Major Features and Changes

Tamanu Desktop

Lab requests enhancements

The lab request workflow has been rebuilt around lab test categories. Tests and panels are chosen from one list, and everything ordered from the same category becomes one lab request with one sample. This cuts the number of samples sent to the laboratory, removes duplicate orders for tests already covered by a panel, and makes it easier for lab staff to see what each sample is for.

Key features

  • Combined test and panel selector - The 'New lab request' screen shows request details, test selection and notes together. Tests and panels appear in one searchable list grouped by category, and each panel can be expanded to show the tests it contains. Selecting a panel disables the individual tests it already covers, so the same test cannot be ordered twice.
  • One request per category - Panels and individual tests from the same category are combined into one lab request, which reaches an integrated laboratory system as one sample.
  • Sample details by category - Sample collection is recorded once per category. 'Collected by' defaults to the logged-in user, and each category can carry a default specimen type, set through the reference data import. Both remain editable.
  • Standard sample label - Sample labels follow one standard size and layout: patient name, date of birth and age, patient ID, request ID with a barcode, date and time collected, and who collected the sample. Label field names follow the facility's language.
  • Automatic label printing - Each facility can choose to show the sample label print screen automatically once every sample on a request has been recorded. This is off by default.
  • Results by panel - The lab request results table and the 'Enter results' modal group results under each panel, followed by individual tests. Results reported below or above what the laboratory can detect, such as '< 0.3', are shown as reported and still flagged as out of range. The results table can be exported.
  • Rejected requests - When an integrated laboratory system cancels a sample, the request is marked 'Rejected' and the requesting clinician receives a dashboard notification. A rejected request cannot change status, and its printout is labelled 'Rejection report'.
  • Lab request listings - The listings show a 'Category' column, with the request's tests and panels on hover. The active requests status filter accepts several statuses at once. The 'Published' listing is renamed 'Finalised', and can be filtered to published, invalidated or rejected requests. The 'Sample collected' tile shows the specimen type.
  • Reflex tests - A new 'Reflex test' visibility status covers tests that cannot be ordered in Tamanu but must exist so a laboratory system can add them when returning results. Tests set to panel only can now be managed in the admin panel.

Medications not dispensed

Pharmacy can now record that an active medication request will not be dispensed, with a reason, and the prescribing clinician is notified straight away. This closes the loop on requests that previously sat in the queue or were removed with no explanation.

Key features

  • Record as not dispensed - A 'Not dispensed' option in the 'Active medication requests' table opens the 'Record medication as not dispensed' modal, where a reason is chosen from a configurable list.
  • Request cancelled, prescription kept - The active request is cancelled, while the prescription itself stays active.
  • Clinician notification - The prescribing clinician receives a notification that opens the encounter's medications with the not dispensed details shown.
  • Permission - Recording a medication as not dispensed uses the same permission as deleting a medication request.

System Administration

Sensitive networks

A sensitive facility has until now kept its confidential data entirely to itself. Sensitive networks let a group of facilities share that data with each other while keeping it from the rest of the deployment. Encounter data recorded at a facility in a network reaches every facility in that network and nowhere else, while facilities outside any network sync as normal.

Key features

  • Networks in reference data - Networks are defined through the reference data import, and each facility names the network it belongs to on the facility sheet.
  • Membership set at creation - A facility's network is chosen when the facility is created and cannot be changed afterwards. Bringing a facility into a network means creating a new facility in that network, which then receives the network's existing data for the patients it syncs.
  • Existing sensitive facilities preserved - Each facility that was sensitive before the upgrade becomes its own network of one, so it continues to receive exactly what it did before.
  • Log in access unchanged - Belonging to a network does not give users access to other facilities in the network. Facility access is still set per user.

Keen to implement sensitive networks?

Please reach out to your Tamanu system administrator/project manager to discuss implementation. Network membership cannot be undone once data has synced, so it needs planning before any facility is created.

🔧System Enhancements

  • Permission to sync patient records - A new permission controls who can use 'Sync patient records' on Tamanu Desktop and sync a patient from Tamanu Mobile. Users without it see a message explaining that the patient is not marked for sync. Patients are still marked for sync automatically by clinical work such as opening an encounter or booking an appointment.
  • Permission for medication due tasks - Medication due tasks on the clinician dashboard have their own permission, separate from viewing the medication administration record. A role can now view when medications were given without receiving the dashboard tasks.
  • Area on dispensed medications - The 'Dispensed medications' table shows the patient's current area, sortable and searchable, so pharmacy can sort medications by ward. Discharged patients show 'Discharged'.
  • Procedure quantity - Procedures have a 'Quantity' field, defaulting to 1, which carries through to the invoice so a procedure performed more than once is charged accordingly.
  • Letterhead - The letterhead title and subtitle can be entered across several lines.

🐛Tweaks and Bug Fixes

Desktop

  • Encounters - Encounter tabs show a standard pointer on hover.
  • Medications - A medication due task completes once its scheduled doses are recorded, even when a PRN medication shares the same time.
  • Admin panel - Lab settings are grouped under 'Labs', the reference data visibility filter has an 'All' option, and the change password layout in the user profile is restored.

Mobile

  • Performance - Patient search, patient screens and sync are faster, particularly on lower-end devices and for patients with long histories.
  • Forms and settings - Submitting a prerequisite form unlocks its dependent forms straight away, and setting changes apply after the next sync without restarting the app. Patient warnings use the device's own dialogs.
  • Lab requests - A category with no orderable tests shows 'No tests or panels found', and tests that fail to load show an error rather than an empty list.

System

  • Sync - Facility servers no longer send deletions received from the central server back to it, which doubled the sync load after a large deletion. Duplicate patient insurance plan records no longer stop sync, and the sync status page no longer lists removed sessions.
  • Settings - Changes to tasking settings take effect without restarting the facility server.

⚠️Critical Upgrade Notes

Required

Lab requests

  • Every lab test panel now needs a category, and all of a panel's tests must belong to that category. Review the panels in your reference data, as a reference data import containing a panel that breaks either rule will fail.
  • Sample labels are printed at one standard size. Check that label printers and label stock at each facility suit it.
  • Where an integrated laboratory system is in use, let the integration team know before upgrading: requests now arrive as one order per category, carrying several panels and tests.

Medication due tasks permission

  • Existing roles are not given the new medication due tasks permission at upgrade. Staff in roles without it will stop seeing medication due tasks on their dashboard.
  • Before upgrading, decide which roles should receive these tasks and grant them the permission.

Medications not dispensed

  • The list of reasons for not dispensing is empty on existing deployments, and a reason is required. Add your reasons through the reference data import before pharmacy staff use the feature.

Sensitive facilities

  • Each existing sensitive facility is moved into its own network at upgrade, with no change to the data it receives.
  • From this release, a new facility is made sensitive by naming a network for it on the facility sheet of the reference data import.
Optional

Lab requests

  • Decide whether each facility should show the sample label print screen automatically, and turn it on where wanted.
  • Set a default specimen type on lab test categories where one is usual.
  • Move tests that only a laboratory system adds from panel only to the 'Reflex test' status.

Permission to sync patient records

  • Every role that can view patients is given the new permission at upgrade, so nobody loses the action. Remove it from roles that should not mark patients for sync.

Sensitive networks

  • To let several facilities share confidential data, discuss network setup with the support team before creating facilities in a network.

Upgrade Steps and Recommended Testing

Required

Lab requests

  • Raise a lab request with a panel and an individual test from the same category. Confirm it creates one request, then record the sample, print the label and enter results.
  • Where an integrated laboratory system is in use, confirm that request reaches it as one sample and that results return to Tamanu.

Medication due tasks permission

  • Log in as a user in a role granted the new permission and confirm medication due tasks appear on the dashboard.

Sensitive facilities

  • On deployments with sensitive facilities, confirm each one still shows its own encounters after upgrade and that they do not appear at other facilities.
Optional

Medications not dispensed

  • Record a medication as not dispensed and confirm the prescribing clinician receives the notification.

General

  • Upgrade an existing Tamanu Mobile device, record some data and sync. Confirm the sync completes and the new records appear on Tamanu Desktop.
  • Set up a new Tamanu Mobile device and confirm its initial sync completes.
